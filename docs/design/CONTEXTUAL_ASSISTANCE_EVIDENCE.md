# Contextual assistance: evidence and design package

Status: research and proposed design, 2026-10-10. Not an implementation approval,
ADR, or change to the active slice. This package extends
[Contextual Program Assistance](CONTEXTUAL_PROGRAM_ASSISTANCE.md).

## Evidence boundary

The research combines a previously reviewed conversation export, newer programming
threads, the coach's authored Training Philosophy draft, a user-approved preference
seed table, and Notes snapshots embedded in those conversations. The export ends
in August 2026; newer conversations are supplementary, not part of that export.
This is a qualitative sample, not a frequency estimate or exhaustive coding of
every transcript. The initial package used conversation snapshots because the Mac
was locked. A read-only live Notes reconciliation on 2026-10-11 completed the
outstanding E4–E7 comparisons and rechecked E1/E3. Private source regions and exact
recorded wording are retained in the companion, not this reusable repository.
An additional seven-client reconciliation on the same date reviewed relevant
exported user-prompt histories, selected decision replies, and all seven live
program notes. E10–E16 below summarize representative paired traces. This extends
coverage; it does not claim exhaustive alignment of every historical program line.

Identifiable source mappings, the personal philosophy, and the preference seed are
kept in a private companion outside the repository. Reusable evidence below is
anonymized and paraphrased. An assistant recommendation is not evidence of
adoption. A saved note is evidence of recorded text, not necessarily performance,
causation, or scientific effectiveness. Later user explanations are retrospective
evidence and must remain distinguishable from contemporary reasoning.

## What the history changes about the design

**Conversation scope, context scope, edit scope, and preference scope are different.**
An exercise question can need the whole session. A cycle review can end in a single
drill. A block substitution can expose an equipment issue elsewhere. A client-specific
constraint must not become a global coaching rule.

Entries include unfinished slots, pasted drafts, requests to review a changed note,
goals/themes before exercise selection, dissatisfaction with an existing block,
observed rehearsal or training results, and equipment constraints. Invocation must
not require selected text or a preselected exercise.

Follow-ups usually refine the job rather than merely select a candidate: correcting
terminology, introducing an exclusion, explaining purpose, changing scope, asking
for fewer options, or testing whether the assistant has respected existing work.
Keep ordinary free-form follow-up primary. Prepared prompts are optional accelerators,
not a replacement for this collaboration.

Recorded outcomes need explicit provenance: proposed, explicitly accepted,
applied through the app, observed in a later note, or adjusted during training.
Refresh detects draft changes; it does not explain their cause or prove performance.

The expanded sample adds two provenance distinctions: **coach-authored before the
reply** versus assistant-proposed, and **planned assessment** versus reported
observation. Neither repeated text nor an assessment label establishes a new fact.
Exercise occurrences also carry decisions about side, setup, cues, role, clock,
and progression. Retaining the name while changing these is partial incorporation,
not a faithful application of the original prescription.

Exclusions need explicit scope: a remaining slot can exclude carries while another
slot retains one; recent overhead work can exclude a candidate today without banning
it next session. Ambiguous mechanism/setup that materially changes a critique is
a valid clarification point. Missing execution evidence alone is not.

## Opinionated, but inspectable

The coach profile should distinguish:

- authored philosophy and explicit commitments;
- user-confirmed tendencies, with exceptions and context;
- inferred candidates not yet confirmed;
- client/session constraints and observations;
- scientific claims awaiting independent evaluation.

The personal seed is not a universal training standard. It includes complementary
pairings, purposeful preparation and conditioning, Olympic-lift direction,
non-machine bias, multidimensional progression, coached challenge, and concise
collaboration. These can influence explanations and candidates without becoming
hard filters. Explicit constraints outrank tendencies. Conflicting instructions
should be surfaced, not reconciled silently.

There is an unresolved coverage detail in the authored sources: movement-pattern
coverage is described both per session and across the program, and category lists
vary. Do not impose a mandatory six-pattern checklist until the coach resolves
the intended coverage window and taxonomy.

Occasional rationale capture belongs near an ambiguous acceptance/rejection:
compact hypotheses, optional ranking or correction, and immediate Skip. Suppress
it when intent is already explicit or remembered. No recurring performance-status
questions. Confirming a local rationale does not automatically approve global
memory; show the proposed scope before remembering it.

Optional later literature review investigates specific claims and invites
reconsideration. It must neither silently rewrite preferences nor equate an
unverified coaching belief with established exercise science.

## Verification and handoff

Documentation-only research package; no production behavior, architecture, tutorial
progress, or active-slice criteria changed. The thread-local synthetic mock was
checked for edit-before-apply, contiguous-block targeting, stale-target blocking,
follow-up, dismissal, desktop appearance, and narrow-width overflow. These checks
do not validate Notes integration, a model, usability, or the real invocation shortcut.
The previously outstanding live note reconciliation is complete for E4–E7, with
E1/E3 rechecked. Seven additional live program notes and representative exported
traces were reconciled for E10–E16, including multiweek examples extending E8.
The wider historical corpus has not received exhaustive paired-note reconciliation.
Unknown execution, causation, and unrecorded dosage
remain unknown; they are not UI-access blockers or negative feedback.

The live comparison strengthened three design requirements: partial incorporation,
separate treatment of exercise/placement/prescription, and visible dependencies
between block edits and equipment-list edits. It also exposed stale content between
two Notes windows; context refresh must use the actual authoritative destination.
The seven-client extension adds concrete evidence for contextual rejection scope,
coach-originated draft provenance, assessment-status preservation, and setup
clarification. It corroborates the approved preference seed without automatically
adding or confirming new durable preferences.

The proposed package remains uncommitted in the existing
`codex/contextual-program-assistance` worktree pending design review. Prior draft
changes in that workstream were preserved. Do not confuse this research completion
with approval to implement or an approved reusable checkpoint.
